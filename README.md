# 螢幕翻譯工具

框選螢幕上任何一塊區域 → 本地 OCR 辨識文字 → 本地小模型翻譯 → **把譯文貼回原本文字的位置**。
全程離線，不會把畫面內容送到任何雲端服務。

```
截圖 (screencapture)
  → OCR (macOS Vision，自動偵測語言；可改用開源的 RapidOCR)
  → 分段 (把換行的句子併成段落再翻，語意才不會斷)
  → 過濾 (數字、時間、單一字母、已經是目標語言的，直接原樣保留)
  → 翻譯 (術語表直接命中 / 其餘送 Ollama + qwen2.5:1.5b，平行 4 條)
  → 把關 (沒翻成中文就重問一次，還是不行就留原文；簡體轉繁體、大陸用詞換回台灣用詞)
  → 覆蓋層 (PyQt6 透明視窗，取樣原圖底色，字級自動縮放)
```

## 安裝到一台新的 Mac

搬過去的時候**不要複製 `.venv`、`build`、`螢幕翻譯.app`** —— 這三個裡面都寫死了舊機器的絕對路徑，
到新機器上會壞掉，要在新機器重新產生。只要帶 `src/`、`config.json`、`requirements.txt`
和那幾支 `.sh` 就夠了。

### 1. 先決條件

```bash
sudo xcodebuild -license accept     # 沒裝過 Xcode 的話可跳過；Homebrew 被擋住時一定要先做這步
brew install python@3.12 ollama
```

沒有 Homebrew 的話先裝：<https://brew.sh>

### 2. 建立環境

```bash
cd 螢幕翻譯工具
./setup.sh
```

會建立 `.venv`、裝好 Python 套件、啟動 Ollama 並下載翻譯模型（約 1 GB，看網速大概幾分鐘）。

```bash
./run.sh --check      # 三關全綠才算成功：截圖 / OCR / Ollama
```

### 3. 做成可雙擊的 App（選用）

```bash
./make_app.sh
```

會產生 `~/Applications/螢幕翻譯.app`，之後用 Spotlight（⌘空白）打「螢幕翻譯」就能開。
這支腳本會把專案路徑寫進啟動器，所以**搬動專案資料夾之後要重跑一次**。

### 4. 開機自動啟動（選用）

```bash
osascript -e 'tell application "System Events" to make login item at end \
  with properties {path:"'"$HOME"'/Applications/螢幕翻譯.app", hidden:false}'
```

要取消就到系統設定 → 一般 → 登入項目移除。

### 5. 給權限

macOS 的權限是綁「哪一個 App 在執行」的，所以**用終端機跑和用 `.app` 跑要分別授權**。

| 權限 | 不給會怎樣 | 設定位置 |
|---|---|---|
| 螢幕錄製 | 截到的是空白，辨識不到任何文字 | 系統設定 › 隱私權與安全性 › 螢幕錄製 |
| 輔助使用 | `⌃⌘T` 全域快捷鍵失效（選單列圖示仍可用）；AI 校稿／修飾抓不到選取的文字 | 系統設定 › 隱私權與安全性 › 輔助使用 |

清單裡找不到的話，先用它框選翻譯一次，系統就會跳出詢問。
**打勾後一定要把程式完全結束再重開**，不然不會生效。

```bash
open "x-apple.systempreferences:com.apple.preference.security?Privacy_ScreenCapture"
open "x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility"
```

## 使用

```bash
./run.sh --check     # 先檢查環境（截圖、OCR、Ollama 三關）
./run.sh             # 常駐：選單列出現「譯」圖示
./run.sh --once      # 只翻一次就結束
./run.sh --lang English --model qwen2.5:3b-instruct   # 臨時覆寫設定
```

常駐模式下有三種用法。

### 一、框選整塊翻譯

- `⌃⌘T`（或選單列圖示 →「翻譯選取區域」）→ 拖曳框選要翻譯的區域
- 譯文會直接蓋在原文位置上
- **按住滑鼠**＝暫時看回原文，**Esc / 雙擊**＝關閉
- 選單列 →「重新翻譯上次區域」可重跑同一塊（例如字幕換了一句）

### 二、游標取詞

選單列 →「游標取詞翻譯」打勾後，滑鼠停在任何一個單字上不動約 0.6 秒，
字的正下方就會浮出一顆氣泡，游標移開就收起來。氣泡裡有三段：

```
close                                  ← 原文
關閉                                   ← 這句話裡的意思（模型看上下文回答）
────────────────────────────────
vt. ①關閉；蓋上；合上 ②關（商店等）…    ← 所有可能的意思（系統辭典，依詞性分列）
vi. ①關閉；蓋上；合上 ②(商店等) 關門…
a.  ①近的，接近的 ②(關係) 密切的…
```

「所有可能的意思」查的是 macOS 內建的《譯典通英漢雙向字典》，不是模型——要 1.5B 把義項全列出來
它會亂編（實測 `windows` 答出「滑鼠」）。辭典離線、一次 2ms，變化形會自動還原
（`Instances` → instance、`saw` 先列鋸子再列 see 看見），同形異義字也都會列（`close` 的關閉與接近）。
義項太多、螢幕放不下時（`set`、`run`）尾端會收成「…」，不會蓋住原文；
嫌太長可以用 `hover_max_senses` 限制每個詞性列幾個，或把 `hover_all_senses` 關掉回到只有兩排的小氣泡。

這本辭典只有英文 → 繁體中文，所以 `target_lang` 不是繁體中文、或停在日文韓文上時，
氣泡只會有上面兩排。`./run.sh --check` 會告訴你辭典有沒有裝；沒有的話打開「辭典」App › 設定，
勾選「譯典通英漢雙向字典」讓它下載。

游標取詞與區域翻譯互斥：開啟游標取詞會清除先前的區域譯文；
開始框選或重新翻譯上次區域時，會關閉游標取詞。需要時可再從選單列開啟。

只截游標周圍 420×90 點的範圍，所以不會整個螢幕跑 OCR，也不吃 CPU。
翻譯時會把整行當上下文一起送進去，`close this window` 的 close 才不會被當成「關門」。

模型和辭典都查不到的時候氣泡不會出現。小模型碰到 `Instances` 這種複數科技名詞會直接回英文原形，
寧可不顯示那一排，也不要浮出寫著英文的假譯文（辭典有收的話，底下的義項照樣會列出來）；
這種常錯的詞建議直接寫進 `glossary`。

需要 `ocr_engine` 設為 `vision`（要單字層級的座標，RapidOCR 給不出來）。
要開機就啟用的話，把 `config.json` 的 `hover_translate` 設成 `true`。

### 三、AI 校稿／修飾自己寫的文字

在任何 App 選取文字 → 點選單列「譯」→

| 選項 | 做什麼 |
|---|---|
| AI 校稿選取的文字 | 只修錯字、注音選字錯誤（會義→會議）、標點，盡量不改原本的寫法 |
| AI 修飾選取的文字 | 修錯字＋把句子改得通順清楚，保留原意，長度差不多 |

約 1 秒後跳出視窗，上面是原文、下面是結果，結果可以先自己再改：
**取代原文**（⌘↩）＝換掉原本選取的文字、**只複製**＝放到剪貼簿不動原文（網頁等不能編輯的地方用這個）、
**取消**（Esc）＝什麼都不做。

- 原理是幫你按 ⌘C 抓選取的文字、按 ⌘V 貼回去，所以需要「輔助使用」權限；
  你原本剪貼簿裡的東西會在完成後還原，不會被蓋掉（選「只複製」除外）。
- 模型用 `rewrite_model`（預設 3B）：校稿要逐字挑錯，1.5B 漏看的比較多。輸出一樣會做簡轉繁和台灣用詞把關。
- 3B 偶爾會改過頭，例如修飾時把「近度」猜成「近況」而不是「進度」——所以才有確認視窗，取代前看一眼。

## 設定 `config.json`

| 欄位 | 說明 |
|---|---|
| `target_lang` | 目標語言，直接寫語言名稱，例如 `繁體中文`、`English`、`日本語` |
| `ollama_model` | 翻譯模型。預設 `qwen2.5:1.5b-instruct`（快）；要更準可換 `qwen2.5:3b-instruct` 或 `gemma3:4b` |
| `ocr_engine` | `vision`（預設，macOS 內建、免費離線、英日韓最準最快）或 `rapidocr`（開源 ONNX 模型，需下載，中文辨識強） |
| `vision_auto_language` | Vision 自動偵測語言，預設 `true`，一般不用動 |
| `vision_langs` | 鎖定語言用，預設空白。**這是優先順序不是集合**：填 `["en-US","ja-JP"]` 去讀日文畫面會辨識不到任何東西，第一個必須是畫面的主語言 |
| `min_confidence` | 低於這個信心值的辨識結果直接丟掉，預設 0.5 |
| `ocr_timeout` | Vision 文字辨識最多等幾秒，預設 20。macOS 偶爾會讓它卡住不回來，逾時就會跳提示請你重開程式 |
| `never_translate` | 不送進模型、原樣保留的字串（產品名、專有名詞） |
| `glossary` | 術語表：`{"instance": "實例"}`。命中就直接用，不問模型（0 延遲、不會錯）；區塊翻譯時則當成提示塞進 prompt。鍵不分大小寫，寫單數就好（`instance` 會蓋到 `Instances`）。**這份表是寫給 `target_lang` 的**，所以 `--lang` 臨時換語言時會自動停用 |
| `block_merge_gap` | 分段的行距容許誤差。程式先量出該區塊的行距中位數，超過「中位數 ×(1+此值)」就換段。版面行距不規則時調大 |
| `font_family` | 譯文字體 |
| `max_workers` | 同時送幾段去翻譯 |
| `hotkey` | pynput 格式，預設 `<ctrl>+<cmd>+t`（⌃⌘T）。修飾鍵要包角括號：`<ctrl>` ⌃、`<cmd>` ⌘、`<shift>` ⇧、`<alt>` ⌥，字母一律小寫。**⌥ Option 在 macOS 是輸入特殊字元用的（⌥T→†），拿來當熱鍵容易打架，不建議** |
| `hover_translate` | 啟動時就開啟游標取詞，預設 `false`（隨時可從選單列切換） |
| `hover_dwell_ms` | 游標要停多久才查詞，預設 600 毫秒 |
| `hover_capture` | 游標取詞的截圖範圍（點），預設 `[420, 90]`。調大能抓到更長的字，但 OCR 會慢一點 |
| `hover_all_senses` | 游標取詞的氣泡要不要列出辭典裡所有的意思，預設 `true`。設 `false` 就只顯示模型給的那一個 |
| `hover_max_senses` | 每個詞性最多列幾個義項，預設 `0`（全部）。設 `3` 的話超過的會收成「…」 |
| `rewrite_model` | AI 校稿／修飾用的模型，空白就沿用 `ollama_model`。預設 `qwen2.5:3b-instruct` |
| `rewrite_timeout` | AI 校稿／修飾最多等幾秒，預設 120 |
| `debug_save_dir` | 填路徑就會把每次的截圖存下來，方便除錯 |

## 換模型

```bash
ollama pull qwen2.5:3b-instruct     # 準一點
ollama pull gemma3:1b               # 更小更快
ollama list                         # 看已安裝的
```
改 `config.json` 的 `ollama_model` 即可，不必改程式。

## 檔案結構

| 檔案 | 負責 |
|---|---|
| `src/main.py` | 進入點：選單列圖示、快捷鍵、流程調度、`--check` |
| `src/capture.py` | 呼叫 `screencapture`，處理 Retina 的點/像素換算 |
| `src/ocr.py` | 兩種 OCR 後端，輸出統一的 `TextLine`；小字自動放大重跑（僅 RapidOCR 需要） |
| `src/group.py` | 把行合併成段落方塊 |
| `src/translate.py` | Ollama 客戶端，平行翻譯＋快取、術語表、輸出把關（重試／簡轉繁／台灣用詞） |
| `src/overlay.py` | 框選介面、結果覆蓋層、取詞氣泡、狀態提示、原圖取色、AI 校稿確認視窗 |
| `src/statusbar.py` | 選單列圖示（原生 NSStatusItem；Qt 的 QSystemTrayIcon 在 macOS 27 點了會閃退） |
| `src/hover.py` | 游標停留偵測、局部截圖、命中單字、查詞 |
| `src/dictionary.py` | 查 macOS 內建的英漢辭典，把一個字的所有義項依詞性列出來（游標取詞用） |
| `src/rewrite.py` | AI 校稿／修飾：送 Ollama 改寫、輸出清理與繁體把關 |
| `src/selection.py` | 模擬 ⌘C／⌘V 抓別的 App 選取的文字、貼回結果，前後還原剪貼簿 |
| `src/selftest.py` | 不碰螢幕的整條流程測試（合成圖 → OCR → 分段 → 翻譯 → 取色） |

## 已知限制

- 譯文比原文長很多時（例如英文縮寫→中文），方塊會往下長一點；極端情況可能蓋到下一行。
- 覆蓋層是獨立視窗，底下的畫面捲動時譯文不會跟著動，捲動後請重按一次快捷鍵。
- 支援多桌面（Spaces）與全螢幕 app：框選視窗設了 `canJoinAllSpaces`，會跟著你所在的桌面出現，不會把你拉回 app 原本的桌面。程式本身是選單列工具（accessory），所以 Dock 不會有圖示。
- 游標取詞的切詞單位：英文一個單字，中日韓是「兩個標點之間的一整段」（沒有空白可切，要真的斷詞得額外裝分詞器）。中英混排的一行會分開處理，停在 `prompt` 上查到的就是 prompt，不會變成整行。
- 停在本來就是目標語言的字上不會有氣泡（查了也沒意義），數字、單一字母同理。
- 游標取詞的「所有意思」用的是 DictionaryServices 沒有公開文件的介面（公開的那一支一次只給第一個詞條）。
  哪天 macOS 改版拿掉了，氣泡會自動退回只顯示模型的翻譯，不會壞掉。辭典本身比較舊，
  `email`、`macOS` 這種新詞沒收，片語（`close down`）也不列。
- `rapidocr` 預設模型對日文假名、韓文較弱，而且一般介面字級（13–15pt）會吞掉英文單字間的空白（`EmptyTrash`）；程式會自動放大重跑來補救，但仍不如 Vision。預設因此用 `vision`。
- 小模型偶爾會吐大陸用語或簡體字。prompt 有台灣用詞對照，輸出端再用 macOS 內建的 ICU
  轉一次簡轉繁、並硬換掉「默認／軟件／網絡」這類詞；「文件」「程序」「數據」「支持」在台灣
  也有正當用法，硬換反而會錯，那幾個只能靠 prompt。要更準可換 3B 模型。
- 術語表沒收的生冷技術詞，1.5B 和 3B 都可能翻錯（實測 `Library` 兩個模型都答「圖書館」）。
  翻不出中文時會自動重問一次，兩次都失敗就留原文——真正的解法是把那個詞加進 `glossary`。
